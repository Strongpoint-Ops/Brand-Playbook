Strongpoint · Design Playbook

Four companies that should look related, not identical.

Strongpoint runs separate operating companies on separate hosts. A visitor who lands on one and follows a link to another should recognise the family immediately — and should never be confused about which company they are dealing with. That is the whole job of this document, and both halves of it matter equally.

Every number here was measured against the live stylesheets, not copied from a brief. Where a property currently breaks a rule, it says so.

Colour

One accent per company, and it has to earn its place numerically.

An accent is not chosen because it looks nice next to the others. It has to clear three gates, all measurable, before it ships.

  • 01At least 4.5:1 against every surface it lands on. The accent is used for link text and small labels, so WCAG AA for normal text is the floor — not the 3:1 large-text allowance. The ground is not the only surface. The parent's accent cleared 4.63:1 on --ground and failed at 4.27:1 on the tinted band one section below; it is #486c8f now, which clears both. The family colour has the same trap in reverse — #6f8fa8 is 5.52:1 on a dark property and 3.04:1 on the light one, so the parent overrides it with #4e6c84 at the same hue.
  • 02At least 60° of hue from every sibling accent. This is the rule that keeps two dark-grounded sites from reading as one. Compare hue against every other company before committing, not just the newest one.
  • 03Never the family colour. Steel blue #6f8fa8 is reserved — see below. A company accent that lands near it makes every cross-property link ambiguous.

What varies, what doesn't

Change several things. Never change these.

Continuity survives a different colour, a different face and a different animation. It does not survive a different skeleton.

Invariant — never per-site

  • The mono eyebrow. 11px, .18em, uppercase, accent-coloured, above every section head.
  • Hairline rules only. 1px, no rounded corners, no drop shadows on dark. Depth comes from the surface step.
  • Registration corner marks on framed panels — the blueprint tell inherited from the parent.
  • Buttons. Display face, uppercase, .06em tracking, 10px/18px, 1px border. Filled = accent, ghost = accent on transparent.
  • Layout. 1180px max, 24px gutter, two columns collapse at 980px, nav collapses at 760px.
  • The family colour for outbound links, with the ↗ glyph.
  • Body contrast ≥ 12:1 and accent ≥ 4.5:1 on the ground. Measured before ship.
  • A real 404 listing every live destination, including sibling companies.
  • No dead links. A host that doesn't resolve is rendered as status text, not an anchor.

Free — vary these on purpose

  • Ground and surface ramp. Light or dark, warm or cool. The parent is light; the operating companies are not.
  • The accent, subject to the three colour gates.
  • The display face, as long as it is condensed.
  • The body and mono faces.
  • Type sizing within the scale — a heavier or lighter headline weight, tighter tracking.
  • A signature motion. One per property, and it must honour prefers-reduced-motion.
  • A dynamic background — canvas field, graph, animated mesh. One per property, behind content, never competing with it.
  • Section rhythm and density. A console can be tight; a founder page should breathe.
  • Secondary data colours — console properties only, for state. Never in a headline or a button.

Motion and SVG — the traps that already cost time

  • 01SVG rotation uses SMIL <animateTransform> about 0 0. A CSS transform-origin on an SVG child resolves against the view-box, so a "spinning" ring orbits the whole canvas and leaves the screen.
  • 02Never bind a drag to an element the drag re-renders. Track drag state on window. Re-rendering destroys the node under the pointer and silently kills its capture.
  • 03Click versus drag is decided by pointer travel (<4px = click), not by the click event — setPointerCapture suppresses the native one.
  • 04Thin-stroke icons and graph nodes have no hit area. Give every one an invisible circle as its real target, and put pointer-events:none on the visible art.
  • 05backdrop-filter creates a stacking context that traps z-indexed children. Portal menus onto <body>.
  • 06Don't size panes with calc(100vh - Npx). Use a flex column and let the content pane take the slack.
  • 07A <button> centres its content vertically even at display:block, so a short card sits lower than its neighbours. Make it a flex column.
  • 08Every grid needs a breakpoint. A two- or three-column grid with no media query is a horizontal scrollbar on every phone. Measure scrollWidth at 390px before shipping.

Motion

Six movements. One per property, and the rest are shared.

Every one of these is running on this page — hover where it says to. A property gets one signature motion. Everything else on this list is shared behaviour that should feel identical everywhere.

Dashed flow — Build's signature

A dash pattern walking along a link. Says "this connection is live" without anything moving position.

stroke-dasharray:3 9 + @keyframes on stroke-dashoffset, 2.6s linear infinite.

Cheap: one animated property, no layout, no paint of new geometry.

Instrument ring — Principal's signature

Tick marks orbiting a fixed core. Reads as an instrument rather than a loading spinner because it is slow — 24 seconds a revolution.

SMIL <animateTransform type="rotate"> about 0 0, inside a translated group.

Never CSS here. A CSS transform-origin on an SVG child resolves against the view-box, so the ring orbits the canvas and leaves the screen.

Rim pulse — attention without blinking

An expanding ring that fades. For one node that needs noticing: a new status, a live connection.

Animate r and opacity, ease-out, 2.8s. Never more than one on screen.

Blinking opacity reads as broken. Expansion reads as a signal.

Reveal — the only entrance animation

A horizontal scale from the left, staggered 80ms. Used once per section at most, never on body copy.

transform:scaleX() with transform-origin:left, 700ms.

Transform and opacity only — both composited, so it cannot cause layout thrash on a long page.

Hover this link

Hairline underline — shared

Links carry a transparent 1px bottom border that takes the accent on hover. The text never moves.

border-bottom-color transition, 220ms. Not text-decoration, which cannot be transitioned consistently.

Reserving the 1px up front is why nothing reflows on hover.

Dim the rest — shared (hover the stage)

Selecting one thing fades everything else to 16% rather than highlighting the selection. How both service maps show focus.

opacity transition, 250ms, on a shared .dim class.

Dimming scales to 25 nodes; highlighting does not — by node ten everything is "highlighted".

Rules

  • 01One signature per property. Two competing animations on a page means neither is a signature.
  • 02Everything honours prefers-reduced-motion. Not "most things". The media query at the bottom of strongpoint.css zeroes every duration token, and any keyframe animation needs its own override on top. The media query does not reach SMIL — an <animateTransform> keeps running for someone who asked for stillness. Call svg.pauseAnimations() from a matchMedia guard; there is one at the bottom of this page to copy.
  • 03Animate transform and opacity. Anything else risks layout or paint on every frame. SVG geometry attributes (r, stroke-dashoffset) are the allowed exception — they are cheap and they are the whole vocabulary of these diagrams.
  • 04Slow enough to read as instrumentation. Ambient loops run 2.5–25s. Anything under a second reads as a spinner, which means "wait", which is not what any of these say.
  • 05Interaction feedback is 150–250ms. Hover, focus and selection. Long enough to see, short enough not to feel laggy.
  • 06No entrance animation on body copy. Text that fades in as you scroll is text you cannot read while it does.

Use it

Two files, in this order.

No build step, no framework, no dependency — the same constraint every property in this group runs under.

<link rel="stylesheet" href="tokens/strongpoint.css">
<link rel="stylesheet" href="tokens/theme-build.css">

The shared file defines every token with a neutral default. The theme file overrides only what that company is allowed to change — fourteen values for a marketing site, twenty-one for the console, which also carries its state palette.

Sites here inline their CSS to stay single-file, so in practice you copy the :root blocks in rather than linking. That is fine. What is not fine is editing a token value in one site and not here — this repo is the source, and a drifted site is a bug in the site.

Adding a fifth company

  • 01Pick a ground. Light is taken by the parent; a second light property needs a reason.
  • 02Pick an accent and run it against all four existing hues. Under 60° from any of them, pick again.
  • 03Check it against the ground. Under 4.5:1, darken or lighten until it clears.
  • 04Pick a condensed display face that is not already in use, and reuse an existing body face — that is the cheapest family tie available.
  • 05Copy a theme file, change the fourteen values, change nothing else.
  • 06Add it to the audit table above, and to every sibling's 404 destination list.
